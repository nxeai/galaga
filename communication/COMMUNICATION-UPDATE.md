# Update communication

## Purpose

Create, enrich, correct, and refresh `COMMUNICATION.md` through one incremental
protocol. Follow the shared update rules in `AGENTS.md`. Learn writing by
channel, audience, and intent through guidance and reviewed samples, while
prioritizing the user's current writing outcome.

## Workflow

1. Read `COMMUNICATION-SPEC.md` and relevant existing guidance, if present.
   Missing or partial knowledge is expected and does not block drafting.
2. Identify the channel, audience, intent, and relevant shared context. Ask
   only when a missing answer materially changes the draft.
3. Gather a few relevant user-authored examples within authorized sources and
   budget. For replies, include the incoming situation and surrounding thread.
   Separate user writing from received, quoted, automated, or unedited
   agent-generated text. Reuse cached evidence.
4. Infer candidate guidance about voice, structure, content, and judgment.
   Distinguish endorsed preferences, aspirations, exceptions, and tentative
   patterns. Without examples, use explicit instructions and reasonable
   defaults without labeling those defaults the user's style.
5. In interactive work, promptly draft the actual requested communication.
   Learn from feedback and available draft-to-final edits. A factual correction
   may reveal missing context rather than a style preference. One edit is not
   a universal rule, and sending is not proof of success.
6. Propose a small set of useful guidance changes and contextualized samples.
   Obtain user review for consequential interpretations and authoritative
   samples; reuse prior endorsement. Scheduled runs queue new review items.
7. Create or revise `COMMUNICATION.md` using the spec's structure. Preserve
   supported nuance and identify weak channel–audience–intent coverage.
   Keep unresolved evidence in `.galaga/`; do not invent samples or preferences.
8. Evaluate against the current writing outcome and available user feedback:
   correct substance, suitable framing, authentic voice, and useful execution.
   Do not claim behavioral validation without evidence or require separate
   calibration exercises before delivering the draft.

## Recurring runs

Review new user-authored writing, explicit corrections, and available
draft-to-final differences incrementally. Prioritize recurring friction,
stale guidance, and underrepresented situations. Batch meaningful proposals
for review; do not interrupt on every run or treat silence as endorsement.

## Completion and retention

A useful partial artifact, approved improvements, pending review, or no change
is a valid outcome. Record coverage and uncertainty honestly. Raw evidence,
provenance, and retrieval progress belong under `.galaga/`.

Deleting a cache, excluding future retrieval, disconnecting a source, and
removing derived guidance are separate actions. Do not claim forgetting while
derived guidance remains. Drafting does not authorize sending or scheduling.
