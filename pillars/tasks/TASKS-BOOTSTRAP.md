# Bootstrap tasks

## Status

This workflow is provisional. The task pillar requires further product design
before the bootstrap should be considered production-ready.

## Purpose

Create the first useful `TASKS.md` by learning how the user forms, prioritizes,
delegates, and evaluates work.

## Initial workflow

1. Read `TASKS-SPEC.md` and the current `TASKS.md`.
2. Establish the user's mandate, goals, sources of work, operational systems,
   authority boundaries, and desired degree of autonomy.
3. Review a bounded set of real candidate, committed, rejected, deferred,
   delegated, completed, and reopened work.
4. Identify candidate decision principles, recurring constraints, ownership
   patterns, and definitions of successful outcomes.
5. Ask the user to review the interpretations and correct missing context.
6. Test the emerging model on representative decide and act scenarios.
7. Create a compact `TASKS.md` from endorsed guidance while preserving gaps
   and uncertainty.
8. Evaluate it against `TASKS-SPEC.md`.

Do not create tasks in an external system, assign work to another person, or
activate scheduled jobs without explicit authority.

## Completion criteria

Bootstrap is complete only when the user has reviewed the resulting model and
representative checks show that it improves task formation or execution. These
criteria should become more specific as the pillar is battle-tested.
