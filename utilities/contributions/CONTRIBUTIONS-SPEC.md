# Contributions specification

## Purpose

Normal use of a private Galaga repository may reveal improvements to the public
framework. Galaga should encourage clean upstream contributions without
exposing personal material.

## Requirements

1. Identify whether a limitation and proposed improvement generalize beyond
   the current user.
2. Restrict the proposed change to framework files.
3. Check the diff for personal facts, samples, source content, credentials,
   identifiers, and other sensitive material.
4. Explain the change and why it belongs upstream.
5. Obtain user approval before creating an external issue or pull request.

Never include unsuffixed personal artifacts or `.galaga/` runtime data in an
upstream contribution. A local customization does not have to become a public
framework rule.
