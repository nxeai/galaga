# Start Galaga

1. Use the immediate task already supplied, or ask one focused question about
   what the user wants help with now.
2. Check the checkout and relevant personal files. In an additional worktree,
   recommend Local or honor the user's existing choice to keep separate
   artifacts. Missing files do not prove no knowledge exists elsewhere.
3. Explain briefly that Galaga will learn what is useful for this task and
   retain personal knowledge locally in Git-ignored files.
4. Invoke only relevant `update-context`, `update-communication`, or
   `update-tasks` skills with the immediate task, available evidence and
   authorized sources, a small effort budget, and the interactive trigger.
   The protocols detect missing or partial files; no first-run flag is needed.
5. Coordinate evidence reuse and questions across modules. Follow their review
   and access boundaries. Do not force every module to initialize or wait for
   full coverage before delivering value.
6. Deliver the useful result, such as a draft reply, and briefly identify
   material gaps and what was learned. Sending or scheduling requires the
   user's authorization.

Use the same process when personal files already exist. Preserve knowledge
and focus on the current outcome; rebuild only on explicit request.
